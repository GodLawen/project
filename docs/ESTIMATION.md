# Оценка задач и расписание проекта HabitTrack

> Статус документа: плановая оценка для лабораторной работы. Оценки не являются фактическим временем выполнения: репозиторий содержит каркас и документацию, рабочая реализация MVP в README обозначена как находящаяся в разработке.

## 1. Принципы оценки

- Единица оценки: человеко-часы.
- Рабочий день для пересчёта: 8 часов.
- Для задач первого Milestone применён PERT: **E = (O + 4M + P) / 6**, **σ = (P − O) / 6**.
- Для остальных задач указана экспертная одноточечная оценка.
- Резерв на риски: **15%** от суммарной оценки.
- Google Calendar (#21) исключён из Release-1: исходная задача прямо помечена как отложенная.

## 6. Зависимости задач

Предлагаемые связи (стрелка означает «предшественник → следующая задача»):

- #4 → #6: сначала нужен работающий бот и обработчик /start.
- #5 → #6, #7: регистрация и привычки требуют схемы БД.
- #6 → #7: привычки создаются для зарегистрированного пользователя.
- #7 → #8, #9, #10: список, удаление и напоминания работают с созданными привычками.
- #10 → #11: планировщик должен определить момент отправки напоминания.
- #11 → #12: кнопка в напоминании запускает отметку выполнения.
- #12 → #13: streak рассчитывается по сохранённым отметкам.
- #10, #13 → #14: тесты проверяют время напоминаний и streak.
- #14 → #15: перед развёртыванием проверяется прохождение тестов.
- #12, #13 → #16: статистика использует отметки и серии выполнения.
- #10 → #17, #18: snooze и изменение времени расширяют механизм напоминаний.
- #5 → #19, #20: админ-статистика и резервное копирование используют БД.

### Критический путь

Для предварительного планирования принят путь: **#4 → #5 → #6 → #7 → #10 → #11 → #12 → #13 → #14 → #15**.

Оценка длительности по этому пути: около **46.4 ч** (с использованием округлённых оценок). Задачи #8 и #9 могут выполняться параллельно после #7 и не входят в выбранную последовательность критического пути. Фактический критический путь следует уточнить после назначения исполнителей и уточнения календарей.

## 7. Спринты и Roadmap

Плановый вариант: три недельных спринта, начало 16.11.2026. Даты — предлагаемый календарный план; их нужно сверить с доступностью исполнителя и текущим сроком M1 в GitHub.

| Спринт | Даты | Содержание | Плановая оценка |
|---|---|---|---:|
| Sprint 1 — текущий | 16–20.11.2026 | M1: #4–#9, основа и управление привычками | 23.8 ч |
| Sprint 2 | 23–27.11.2026 | M2: #10–#15, напоминания, отметки, streaks, тесты, VPS | 27 ч |
| Sprint 3 | 30.11–04.12.2026 | M3: #16–#20, статистика, гибкие напоминания, администрирование, бэкапы | 18 ч |

Sprint 1 предлагается пометить как **Current sprint** в GitHub Project. В рамках каждой недели задачи могут выполняться параллельно, если зависимости соблюдены.

## 8. Что требуется настроить в GitHub вручную

1. Оставить существующий M1 и проверить, что в него входят #4–#9.
2. Создать M2: «Напоминания и выполнение», добавить #10–#15.
3. Создать M3: «Release-1», добавить #16–#20.
4. В GitHub Project добавить поле Estimate (число, часы) и внести оценки из раздела 4.
5. Добавить связи blocked by / blocking по разделу 6.
6. Создать три итерации по датам из раздела 7 и пометить Sprint 1 текущим.
7. Включить Roadmap view с датами Milestones/итераций.
8. Для сдачи лабораторной приложить ссылки на Issues, Project и PR.

Поэтому это оценки объёма будущей реализации, а не оценка оставшейся работы по фактическому коду.
